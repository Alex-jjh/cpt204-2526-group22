Part One · Sorting Three algorithms in trial
Speaker · Teammate  ·  0:30
I.
Task A  ·  Algorithm Evaluation

Three sorts, three datasets,
three different theatres of war.

i. Bubble

Bubble Sort

Adjacent compare-and-swap. We carry Liang's early-exit flag — the moment a full pass does no swaps, the array is provably sorted and we return.

complexityO(n) · O(n²)
ii. Quick

Quick Sort

Lomuto partition with a median-of-three pivot. Sorting three candidates and placing the median at hi dodges the classic O(n²) trap on already-ordered input.

complexityO(n log n) avg
iii. Merge

Merge Sort

Top-down divide and conquer. Stable in every case — ties keep their relative order. Trades O(n) auxiliary memory for guaranteed performance.

complexityO(n log n) all
A. nearly sorted Bubble should sweep one pass, find no swaps, and exit. ›
B. random Quick should dominate — cache-friendly, in-place, low constants. ›
C. many ties Merge's guaranteed stability becomes a feature, not a footnote. ›

Part Two · Graph Week 10 follow-up  ·  the two swaps that fix O(V³)
Speaker · Alex  ·  0:35
§ 2.3a
Follow-up  ·  the lecturer’s open question, answered concretely

Two data structures, working as a pair, drop O(V³) to O((V+E) log V).

Week 10 — WeightedGraph.getShortestPath As given 
while (T.size() < getSize()) {
  // scan all V to find smallest cost
  for (int i = 0; i < getSize(); i++)
    if (!T.contains(i) && cost[i] < min)  « O(V) per check
      …
  T.add(u);
  for (Edge e : neighbors.get(u))
    if (!T.contains(e.v) && relax)         « O(V) per check
      …
}
T is an ArrayList<Integer>, so every T.contains() is a linear scan. The outer while runs V times; the inner scan runs V times; contains costs V. Three V’s nested — O(V³), ≈ 10⁹ ops on our graph.

The Two Swaps

Role in the loop W10 textbook Our implementation
Membership test
“is v already settled?” ArrayList<Integer> T
O(V) per check HashSet<String> settled
O(1) per check
Extract-min
“cheapest unsettled v?” Linear scan over cost[]
O(V) per pop PriorityQueue — binary heap
O(log V) per pop
O(V³)→O((V+E) log V)
On V = 1 000, E = 2 600:
~10⁹ ops  →  ~3.6 × 10⁴ ops  ·  ≈ 30 000× cheaper.
The key insight The two swaps only work as a pair. A heap finds the minimum in O(log V), but only if the “already settled?” check is also fast — otherwise the heap saves us nothing. Replacing just one of the two ArrayList roles would still leave a quadratic loop. The optimisation lives in the interaction, not in either structure alone.

§ 2.3
Justification  ·  Heap Dijkstra over textbook alternatives

Sparse graphs reward the algorithm that ignores absences.

Textbook Dijkstraadjacency-matrix scan
O(V²)~ 10⁶ operations
Floyd–Warshallall-pairs shortest paths
O(V³)~ 10⁹ operations
PQ-Dijkstra + adjacency listour implementation
O((V+E) log V)~ 36 000 operations
28×
cheaper than textbook adjacency-matrix Dijkstra at V = 1 000, E = 2 600. Our graph has 0.5 % density — a matrix would waste 192× the space, and a dense scan would touch a thousand cells when only five are real neighbours.

Alternatives Considered · § 2.5

BFS Correct only on unweighted graphs — ruled out: ours carries weights.
A* Requires a geometric heuristic — ruled out: we have no coordinates.
Bellman–Ford Handles negative edges — we have none, and it is O(VE), 26× slower.

Chapter Three  ·  Object-Oriented Design
Two interfaces, five packages, four pillars.
i.
model.*  — immutable value objects (Candidate, Edge, PathResult).
ii.
io.*  — a single CsvReader; nothing else touches the disk.
iii.
sort.*  — three sorters behind one Sorter interface.
iv.
graph.*  — Graph plus DijkstraShortestPath behind ShortestPathFinder.
v.
app.*  — the driver; orchestrates, never computes.
Adding a fourth sort (Heap?) is one new class. Adding BFS is one new class. Main changes nothing.
Encapsulation
Candidate is immutable; every field private final, accessor-only. State leaks are impossible by construction.
Inheritance
BubbleSort, QuickSort, MergeSort all implement Sorter — interface inheritance, not class.
Abstraction
Two interfaces — Sorter and ShortestPathFinder — are the only contracts Main sees.
Polymorphism
Main iterates a List<Sorter>; dynamic dispatch picks the implementation at run-time.

§ 3.1
Data structures  ·  what we picked, and why
A collection is a contract; pick the one whose costs you intend to pay.
Candidate lists
ArrayList<Candidate>
Sort-then-iterate workload. O(1) random access; contiguous memory is cache-friendly. No mid-list inserts — so we pay nothing for them.
In memory A backing array of contiguous slots.
L0001[0]
L0002[1]
L0003[2]
L0004[3]
…[…]
L0999[998]
L1000[999]
Address of slot i is just base + i × 8 — that's why get(i) is O(1) and the sort algorithms can swap adjacent slots without chasing pointers.
Graph adjacency
HashMap<String, List<Arc>>
O(1) lookup of a node's neighbours by ID. Sparse-graph efficient: 2 600 edges, not 1 000² entries. Adjacency, not matrix.
In memory Bucket array; each bucket holds one node's neighbour list.
bucket[h(L0001)] L0001value → Arc(L0002, 2), Arc(L0340, 4) bucket[h(L0105)] L0105value → Arc(L0106, 1), Arc(L0474, 3), Arc(L0592, 9), Arc(L0130, 10) bucket[…] … 998 more buckets, one per node
Read as: key L0105  →  value = its neighbour list [Arc(L0106,1), Arc(L0474,3), Arc(L0592,9), Arc(L0130,10)]. All four Arcs belong to L0105 — they are L0105's outgoing edges. Arcs in the same list are not connected to each other. adjacency.get("L0105") hashes the key, jumps to one bucket, returns that whole List<Arc> in O(1).
Dijkstra frontier
PriorityQueue<Entry>
Binary heap. O(log V) extract-min — the reason we beat O(V²) on every shortest path query.
In memory A binary heap — every parent ≤ both children. poll() always returns the root.

Every container we picked sits on Java's standard hierarchy — nothing exotic, nothing imported. The library list stays empty; the asymptotic budget stays honest.
A note on Edge vs Arc. The graph is undirected, yet each edge is stored twice in the adjacency list — once as a directed Arc from each endpoint. Why pay double the memory? Because Dijkstra's inner loop asks "give me node u's neighbours" on every pop. With a single shared Edge, that loop would have to ask "which end is me?" on every access — a string comparison inside the hottest path. Storing two directed Arcs lets arc.to() be a direct field read. Space-for-time, where the time is the inner loop of every query.
